# Task Manager — Backend

Spring Boot REST API that stores tasks for the React frontend in `../frontend`.
See the [top-level README](../README.md) for how to run the whole app together.

## Tech stack
Java 25, Spring Boot 3.5 (Web, Data JPA, Validation), H2 (local), PostgreSQL
(production), Maven, Lombok.

## Run it
```bash
mvn spring-boot:run
```
Starts on `http://localhost:8080`. Data resets every restart (in-memory H2) — fine
for development, not for production.

For hosting, activate the `prod` profile and provide `DB_HOST`, `DB_PORT`,
`DB_NAME`, `DB_USER`, `DB_PASSWORD`, and `CORS_ALLOWED_ORIGINS`. The production
profile uses PostgreSQL and disables the H2 console. The repository-root
`render.yaml` and this folder's `Dockerfile` provide the Render setup.

## API reference

All endpoints are scoped by `userId`, a browser-local workspace ID generated by
the frontend. This separates task lists but is not authentication or access control.

| Method | Path              | Body / Query        | Notes                              |
|--------|-------------------|-----------------------|--------------------------------------|
| GET    | `/tasks?userId=`  | —                     | all tasks for that user              |
| POST   | `/tasks`          | Task JSON             | `userId`, `title`, `date` required   |
| PUT    | `/tasks/{id}`     | Task JSON             | full field replace                   |
| PATCH  | `/tasks/{id}/done`| —                     | flips the `done` flag                |
| DELETE | `/tasks/{id}`     | —                     | 204/404                              |

**Task JSON shape** (matches the frontend's `TaskModal` form exactly):
```json
{
  "userId": "browser-workspace-id",
  "title": "Learn Spring Boot",
  "notes": "Finish phase 1",
  "date": "2026-10-01",
  "start": "09:00",
  "end": "10:30",
  "category": "study",
  "priority": "medium",
  "done": false
}
```
`category` is a free-form string (the frontend currently offers study/teaching/gym/personal).
`priority` must be `high`, `medium`, or `low`.

## Validation & errors
- `userId`, `title`, `date` are required on a task.
- A validation failure returns 400 with a `fields` map of what's wrong.
- Requesting/updating/deleting a task that doesn't exist returns 404.

## CORS
`CorsConfig` allows the origin in `CORS_ALLOWED_ORIGINS`, defaulting to
`http://localhost:5173` for local development. Set it to the exact hosted frontend
origin for deployment.

## Inspecting the database
While running: `http://localhost:8080/h2-console` — JDBC URL `jdbc:h2:mem:taskdb`,
user `sa`, no password.
